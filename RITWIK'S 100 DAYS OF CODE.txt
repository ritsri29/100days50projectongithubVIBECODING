RITWIK'S 100 DAYS OF CODE
50 PROJECTS FOR GITHUB
========================================

Goal: Build 50 practical projects in 100 days and publish them on GitHub.
Focus: Computer Science, Maths, Python, Web Development, AI and Software Engineering.
Suggested routine: 45-75 minutes on school days; 1-2 hours on weekends.
Note: These are roadmap targets, not claims that the projects are already complete.

GITHUB PUBLISHING CHECKLIST
---------------------------

For every project:
[ ] Give the repository a clear, lowercase name.
[ ] Test the project and document how to run it.
[ ] Add a README.md with purpose, features, tech stack and setup steps.
[ ] Add screenshots or a GIF when useful.
[ ] Remove API keys, passwords, tokens and personal data.
[ ] Add an appropriate .gitignore.
[ ] Use meaningful Git commit messages.
[ ] Mention known limitations and unfinished features honestly.
[ ] Add a license if appropriate.
[ ] Deploy a live demo when practical.

DAILY ROUTINE
-------------

10 minutes: Review previous code.
25-40 minutes: Build the main feature.
10 minutes: Test and fix bugs.
5-10 minutes: Commit code, update README and log progress.

School days: Aim for 45-75 minutes.
Weekends: Aim for 1-2 hours when available.
Reduce the session during exams or busy school days; consistency matters more than rushing.

DAY 1 STARTER TASK
------------------

1. Create a GitHub repository named 100-days-of-code.
2. Start the ritwik-portfolio project.
3. Build Hero, About, Skills and Projects sections.
4. Add a README and make the first meaningful commit.
5. Record the Day 1 update in PROGRESS.md.

FINAL REMINDER
--------------

These 50 items are project targets, not completed work. Prioritize quality over quantity:
15 complete, tested and well-documented projects are more valuable than 50 unfinished repositories.
